# CVE Center search motion research notes

- The [W3C CSS Transitions Level 1 specification](https://www.w3.org/TR/css-transitions-1/) defines running transitions, interrupted transitions, and reversing-adjusted start values/shortening factors. A class-driven CSS transition can reverse naturally from its current interpolated value when scroll direction changes.
- [MDN’s `transition` reference](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/transition) describes transitions as per-property duration, timing function, and delay. The prior 420 ms morph used a symmetric, non-overshooting curve and retained the reduced-motion override.
- [Material Design 3 Search Guidelines](https://m3.material.io/components/search/guidelines) recommend a persistent, discoverable search field near the content it searches. In adaptive layouts, the search should stay in its pane, scale with that pane, and keep internal content anchored to the sides as width changes. This supports retaining the real input with its icon and query left-aligned while its strip narrows around the center.
- [web.dev’s high-performance CSS animation guide](https://web.dev/articles/animations-guide) recommends prioritizing `transform`/`opacity`, avoiding layout/paint animation unless required, and inspecting animation runtime for dropped frames. This treatment needs a visibly narrower editable field, so width/height changes are used only for the one small dock; actual in-flight frames, long tasks, and frame gaps are measured rather than inferred from endpoint screenshots.
- Public GitHub search results did not surface a directly comparable, accessible vanilla-JS implementation of a sticky search control that also preserves this app’s query, filters, history, and touch-navigation behavior. No unrelated implementation was copied; the existing static app structure and CSS state model remain the reference.
- The final rail is an always-real input framed by a straight-edged SVG rail with concave ends. It compacts near the centered sticky threshold, then releases from sticky positioning at the feed boundary computed from the CSS-declared compact target height (not the animated in-flight height). On upward scroll/resize, the original anchor re-enters just below the header; the header Search control and `/` shortcut return focus to the retained field, while Escape blurs without clearing its query. The header action is present only while the field has scrolled away.
- Final Chromium audit (2026-10-04) covered 1440×900, 1440×624, 1024×900, 768×800, 390×844, 360×800, 320×740, and 320×640: all zero CVE rows intersecting the dock, no horizontal overflow, Search action fitting at every size, query/filter retention, keyboard/pointer/touch return, and reduced-motion behavior.
- A 520 ms headless-Chromium `requestAnimationFrame`/Long Tasks probe sampled 33 frames per viewport. At 1440×900 and 390×844 the average gap was 16.67 ms (P95 16.70/16.80 ms, maximum 16.8 ms), with zero gaps above 20 or 33 ms and no Long Tasks. This is a measured result for this local Chromium run, not a cross-device performance guarantee.

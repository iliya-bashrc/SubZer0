# CVE Center search motion research notes

- The [W3C CSS Transitions Level 1 specification](https://www.w3.org/TR/css-transitions-1/) defines running transitions, interrupted transitions, and reversing-adjusted start values/shortening factors. The search remains a class-driven CSS transition rather than a hand-built animation timeline, so changing scroll direction can reverse naturally from the current rendered value.
- [MDN’s `transition` reference](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/transition) confirms that the transition is a combination of per-property duration, timing function, and delay. The morph now uses a 420 ms symmetric, non-overshooting curve for geometry and a coordinated 210 ms cross-fade; the existing reduced-motion override still collapses all transition timing to effectively immediate.
- Public GitHub search results did not surface a directly comparable, accessible vanilla-JS implementation of a sticky search capsule that also preserves this app’s query, filters, history, and touch-navigation behavior. No unrelated implementation was copied; the existing static app structure and CSS state model remain the reference.
